# Requirements traceability

Every requirement in Chapter 4 (Section 4.2), mapped to the code that implements
it, the tests that check it, and the evidence that demonstrates it. The
requirement text is quoted from the thesis. Requirements that are not fully met
say so, and name the gap.

**Status** is one of **Done**, **Partly** (some of it exists; the gap is named)
or **Not implemented**.

Paths are relative to the repository root. Python test counts are from the run
recorded in `docs/test-results.xml`: **386 tests, all passing** (2026-10-29, with
a database available, so the database-backed tests ran). The interface adds 19
component tests and 10 end-to-end tests, the latter run in both Chromium and
WebKit for 20 runs in total (`docs/evidence/e2e_browsers.txt`), one of which is
the NFR-01 browser timing.

### What would close the gaps

1. **NFR-02.** FR-09 and NFR-03 are now closed: the `ExplanationGenerator` exists as a separable component, and coverage is measured. The remaining gap is the figure itself, 79.2% against 85% on development. It is not a defect to be fixed in the generator — every variant whose wording the vocabulary knows already clears 85%. Closing it means widening the vocabulary so fewer workers reach no occupation, which is the cold-start limitation, not an explainability one.
2. **IR-03.** pgvector, deferred to #45 by decision, and planned as a Chapter 5 comparison rather than a feature.
